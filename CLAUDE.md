# MonitorAgent

> **Keep this file in sync with every change.** When modifying architecture, schema, UI layout, data sources, or project structure, update the relevant section here first.

macOS menu bar app that displays usage statistics for Claude Code, Codex, and Cursor.

## Stack

- Swift 5.10 / SwiftUI + AppKit / macOS 14+
- SQLite via GRDB (Swift Package Manager)
- Build: `swift build`
- Test: `swift test`
- Release build: `swift build -c release`
- Release toolchain: GitHub Actions `macos-26` runner + Xcode 26.6 + macOS 26.5 SDK
- Run locally: `swift run MonitorAgent &`
- Stop locally: `pkill -f MonitorAgent`

## Data Source

Usage is derived from first-party local logs or the signed-in provider's own usage API, with no analytics intermediary.

`Settings > General > Monitored Agents` controls which sources participate in routine monitoring. Claude Code, Codex, and Cursor are enabled by default. A disabled source is not discovered, read, authenticated, or refreshed; disabling a source also cancels its in-flight usage sync, stops Cursor's active usage request, and gates the final usage-database commit so a disabled source cannot write after the setting change completes. Routine local-log parsing streams complete lines from bounded read chunks and checks cancellation during both reads and line scanning. A disabled source is also excluded from the panel filters, `All` aggregates, and new subscription quota requests; an already-started quota request may finish but its result is discarded and its canceled cycle participant no longer blocks the replacement refresh cycle. Existing cached records and saved subscription dates are retained so re-enabling a source restores its history and resumes incremental monitoring in a new refresh cycle; it never revives canceled usage work from an older cycle. If every source is disabled, the panel refresh coordinator stops and the panel shows a settings-oriented empty state. The explicitly requested Data rebuild remains a full-source cache repair and is not limited by this routine-monitoring selection.

| Source | Path | Parser |
|--------|------|--------|
| Claude Code | `~/.claude/projects/**/*.jsonl` | `ClaudeLogParser` — extracts `message.usage` from `type == "assistant"` lines |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` + `~/.codex/archived_sessions/rollout-*.jsonl` | `CodexLogParser` — stateful, extracts `token_count` events with heartbeat dedup, requires per-turn `last_token_usage`, and stores uncached input tokens |
| Cursor | `https://api2.cursor.sh/aiserver.v1.DashboardService/*` | `CursorUsageService` and `CursorSpendService` — read Cursor's current local login session from `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb`, fetch only the signed-in user's token events and spend, and map Cache Write to Cache Creation |

Cursor authentication is read from Cursor's local `state.vscdb` for each visible-account verification and refresh and is sent only to `https://api2.cursor.sh`. MonitorAgent never persists or logs Cursor access or refresh tokens. One shared, single-flight Cursor account session resolves `GetMe` for token and spend work; forced verification shares only a request that is still in flight and never reuses a completed account result. Its network request has an independent lifecycle, every caller including the request starter waits with its own cancellation, and cancellation failures are never allowed to poison another caller. Cached Cursor data may remain on disk after an authentication or API failure, but it participates in Cursor, All, Activity, heatmap, model, and tooltip presentation only after the currently verified account identity matches the cache identity stored in `sync_state`; entering an unverified, verifying, changed-account, or mismatched-identity state immediately removes old Cursor-derived presentation without deleting the cache. Every asynchronous presentation query binds to the verified account plus a monotonic database revision and discards its entire result if Cursor records are replaced before publication, including A/B/A replacements; its final revision validation and state publication execute under the same database lifecycle lock so replacement cannot enter between them. Panel opening and selecting Cursor verify the account even when the normal refresh interval suppresses a full refresh. A resolved account may start work only while its verification generation, panel visibility, monitored-Agent scope, and non-rebuild lifecycle are still current; starting Data Rebuild invalidates pending account resolutions. Cursor usage sync requests coalesce only when both the expected account identity and cancellation domain match and no different queue submission intervenes; every request and Data Rebuild exclusive operation shares one atomic FIFO submission order, so work published before a rebuild barrier runs before it and work published afterward runs after it. A queued request retains its sync manager until every waiter completion is delivered. Changing accounts triggers an atomic full replacement of Cursor records and spend snapshots, and every verification, sync, refresh, and failure callback must match its originating generation before changing presentation state. Temporary account verification never rewrites the user's selected Heatmap year. Cursor spend checks its five-minute TTL only after authentication and reads snapshots by the explicitly verified identity. Selection-driven spend work has its own cancellation lifecycle and cannot commit after its filter, panel, monitored-Agent, verification, or rebuild scope becomes stale; a pending forced refresh retains its originating cancellation domain when later automatic requests target the same scope. It uses two `GetDailySpendByCategory` requests over the selected local-time range with `groupBy = MODEL`: authoritative `ALL` supplies Total Usage and authoritative `ON_DEMAND` supplies On-Demand. Only an explicitly present empty `dailySpend` array is an authoritative zero; missing, null, malformed, or failed values remain unavailable and never become zero. Cursor's DashboardService is an internal API, so response transfer and parsing are bounded and fail closed when the protocol changes. Transport sessions use weak delegate ownership and invalidate when their transport is released.

Database:

- Installed app: `~/.monitor-agent/monitor.db`
- Bare executable (`swift run`, any build configuration): `~/.monitor-agent/development/monitor.db`

The database is a derived local cache, not the source of truth. Only the installed `.app` with bundle identifier `com.hd1987.monitor-agent` uses the production database paths. Bare executables isolate both the active and temporary rebuild databases under `~/.monitor-agent/development/`, regardless of build configuration. Database open failures keep the app available so the rebuild action remains accessible. `Settings > General > Data` can rebuild the cache while Claude Code and Codex continue writing logs. The rebuild snapshots each discovered file's identity and byte boundary, streams only complete JSONL lines within that boundary into the active environment's `monitor-rebuild.tmp.db`, performs one bounded catch-up pass for newly created or appended data, refreshes Cursor usage into the temporary database, restores only validated spend snapshots whose account identity matches that successful Cursor refresh, validates the temporary database and source coverage, then replaces `monitor.db` only after every pre-replacement stage succeeds. Source files may grow during a rebuild, but deletion, replacement, truncation, read failure, or database write failure aborts without replacing the active database. If cached Cursor token or spend data exists, a Cursor authentication or API failure also aborts the rebuild so that cache cannot be erased while offline. An existing nonempty database is also preserved if the rebuilt result contains no requests. After replacement, one immediate incremental sync captures activity written after the catch-up boundary.

The rebuild path filters JSONL ranges by the minimal Claude/Codex event markers before copying or JSON decoding, uses accelerated newline searches, and commits parsed records plus parser state once per source file. The temporary database retains SQLite's normal durability throughout the rebuild so a validated replacement is already durable. The rebuild sheet shows phase, byte, file, and request progress and allows cancellation while the temporary database is being built. Cancellation cleans up the temporary database without modifying the active database. Original Claude/Codex logs and settings are never modified. Any leftover temporary rebuild database is cleaned up on app startup.

Incremental sync resets a file's parser state when the source file is truncated or replaced with a smaller file. Parsed records and the matching `sync_state` offset are committed in one database transaction so an offset never advances past records that failed to persist. Rebuild waits for the sync queue to become idle, and database reads, writes, close, reopen, and replacement share one lifecycle lock so the active database cannot be replaced during an in-flight operation.

### Schema

```sql
request_logs (
    request_id TEXT PK,          -- "session:{msg_id}" or "codex:{sid}:{turn}"
    app_type TEXT,               -- "claude" | "codex" | "cursor"
    model TEXT,
    input_tokens INTEGER,        -- uncached input tokens; Codex raw input includes cache and is normalized
    output_tokens INTEGER,
    cache_read_tokens INTEGER,
    cache_creation_tokens INTEGER,
    session_id TEXT,
    created_at INTEGER           -- Unix seconds
)

sync_state (
    file_path TEXT PK,
    byte_offset INTEGER,         -- incremental read position
    record_count INTEGER,
    session_id TEXT,              -- Codex: carried across lines
    model TEXT,                   -- Codex: carried across lines
    last_total_input_tokens INTEGER,  -- Codex: heartbeat dedup across sync batches
    last_total_output_tokens INTEGER, -- Codex: heartbeat dedup across sync batches
    last_modified INTEGER,
    last_synced_at INTEGER
)

cursor_spend_snapshots (
    account_identity TEXT,
    range_key TEXT,
    range_start_ms INTEGER,       -- selected local-time lower bound; NULL for All Time
    range_end_ms INTEGER,         -- selected local-time exclusive upper bound; NULL for All Time
    total_cents INTEGER,          -- authoritative ALL response; NULL when unavailable
    on_demand_cents INTEGER,      -- authoritative ON_DEMAND response; NULL when unavailable
    total_updated_at INTEGER,
    on_demand_updated_at INTEGER,
    last_accessed_at INTEGER,
    PRIMARY KEY (account_identity, range_key)
)
```

## UI Layout

**Menu Bar**: Robot icon (template image from bundled SVG). Left-click opens the panel and triggers one unified refresh cycle for every monitored Agent and its configured subscription quota when the elapsed time since the last refresh start meets the selected Refresh Interval. While the panel remains visible, the single Refresh Interval controls every periodic refresh through one non-overlapping coordinator; hiding the panel stops the timer, and monitoring no Agents keeps it stopped. `Never` disables the repeating timer and uses the shared default interval of 1 minute for this panel-open check. Data rebuild pauses the whole refresh coordinator and restarts it with an immediate enabled-source cycle after completion or failure. Enabled Claude Code and Codex local results reload as soon as their file sync completes, without waiting for an enabled Cursor network request; Cursor results trigger a second reload after a successful API refresh. A user-configured global shortcut can toggle the panel from any app; it is unassigned by default, requires at least one modifier, can be cleared, and is registered immediately after Shortcuts settings are saved. Shortcut conflicts prevent the Shortcuts save and keep the previous shortcut active. Right-click opens About / General / Shortcuts / Extensions / Config / Prompt / Check for Updates / Quit. Installed apps load the SwiftPM icon bundle from `Contents/Resources`; bare development executables load the SwiftPM build bundle. Update-check dialogs use a SwiftUI-hosted panel with structured states for checking, up-to-date, new version, downloading, installing, completion, and failure. Checks, downloads, and installs are single-flight. Native window closure follows the same cancellation path as the dialog action during checking and downloading; installation disables the close button and rejects window-close requests because app replacement cannot be interrupted safely. Downloads are moved to unique temporary archives with checked errors, then removed after installation; extracted apps must contain the executable and SwiftPM menu-bar resource before replacing the installed app. Activation policy is `.accessory` (no Dock icon). Re-clicking the app icon shows the panel via `applicationShouldHandleReopen`.

**Panel** (top → bottom): The borderless main panel uses the same opaque semantic window background as General, 16pt continuous corners, and the same native macOS window shadow as the General settings window, without a separate edge border. Main-panel secondary and tertiary text use explicit theme-aware contrast levels so labels remain readable when the panel loses focus. Content hierarchy comes from spacing, typography, and quiet theme-aware grouped surfaces that match General's darker inset groups instead of reversing the hierarchy with bright cards on a gray panel. Interactive controls provide immediate press feedback with critically damped spring motion; Reduce Motion removes scaling while preserving short opacity feedback. The in-panel shortcuts are customizable in Settings > Shortcuts (defaults in parentheses): Hide Panel (`Esc`) hides the panel even when it is pinned; Cycle App Filter (`Tab`) cycles the app filter forward and reverses with `Shift`; Reset Panel Position (`Return`) resets the panel below the menu-bar icon; Refresh Data (`R`) starts a unified refresh and resets the next automatic refresh interval; Toggle Activity Chart (`C`) opens or closes the current range's Activity detail; Toggle Pin (`P`) pins or unpins the panel. Panel shortcuts allow single keys and are matched by keyCode plus modifiers while the panel has focus.

The reset-credit tip uses a compact width, labels its date column `Expires`, and applies expiration urgency colors only to each row's dot. Subscription-expiration and reset-credit tips use the same hover state machine and a transparent bridge across the visual gap, so they remain presented while the pointer moves from their trigger region onto the tip itself without relying on a timed dismissal delay. One provider-and-tip owner is active at a time; a new trigger replaces the previous owner, an outgoing tip cannot reclaim ownership during its removal transition, and removing its provider from the visible quota list clears the owner even when the list becomes empty.

Quota card visibility, expiration presentation, refresh participation, and cache restoration use the same `QuotaSettings` instance owned by `AppStore`.

Disabling the selected Agent resets the panel to `All` and closes any Activity detail. All uses the existing menu-bar icon, Claude Code and Codex use their existing provider icons, and Cursor uses the supplied Cursor SVG; inactive filters show their icon alone, while the selected filter expands to show its icon and label. The segmented control, tool-button group, and date control share a compact 28pt outer height and one vertical centerline. The tool-button group and date control have no container background, and the tool icons use a restrained 46%-strength tertiary panel foreground with 4pt spacing so they remain discoverable without competing with the filters and date. Every top tool uses the same quiet circular hover surface and press feedback without changing its icon color. The Activity chart toggle sits immediately after pin and displays the bundled template icon for the current Activity chart style (`linechart.svg` or `barchart.svg`); while the detail is open, only its icon changes to Activity blue and no persistent selected background is shown. The refresh button follows the Activity chart toggle, starts one unified refresh cycle for every enabled data source, and resets the next automatic refresh interval from the actual start of that cycle. It is disabled when no Agents are monitored. The disabled refresh icon rotates only while executing a cycle triggered by the button or its shortcut, except under Reduce Motion; panel-open, timer, settings-change, and rebuild-completion cycles keep the icon static. Every actual cycle start begins one shared 10-second manual-refresh cooldown for the button and shortcut; cooldown requests are ignored without moving the automatic schedule, and the disabled icon uses a lighter color without showing a countdown. The rule also applies when Refresh Interval is `Never`. A request made after cooldown while a cycle is still active coalesces into at most one pending cycle. System-triggered panel-open, timer, settings-change, and rebuild-completion cycles do not wait for the manual cooldown. The selected app filter uses a restrained 38%-strength Activity Input Tokens blue tint with the theme's primary text color. App-filter labels always stay on one line, with the central drag gap shrinking before the filter compresses. All non-interactive FilterBar whitespace acts as the borderless panel's drag region: the full-width upper and lower padding strips, the left and right side margins, and the gap between the app filter and right-side controls. Interactive controls and the spacing between adjacent controls remain click-only. Dragging keeps the panel inside the current screen's visible frame, and closing then reopening retains the dragged position for the current app session. The reset button returns the panel below the menu-bar icon; restarting the app also restores that default placement. The pin, Activity chart, refresh, reset, and General icons provide hover help. An enabled pin stays filled and uses the same Activity blue only while the main panel has focus, returning to the subdued icon color when focus moves elsewhere. The General button opens settings and lets an unpinned main panel close through its normal focus-loss behavior; a pinned panel remains visible. While the date popover is open, its own controls remain interactive, but one click anywhere in the main panel only dismisses the date popover and is consumed before it can activate an underlying control. Opening the panel includes every monitored provider with a configured expiration in the immediate unified refresh cycle. The shared Refresh Interval choices are `1 min`, `2 min`, `5 min`, and `Never`, defaulting to `1 min`; the top app filter only changes which quota cards are displayed and never triggers a quota request.
